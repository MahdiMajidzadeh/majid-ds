mds:input

Flux's input, storing Latin digits whatever keyboard typed them.

Persian keyboards type ۰۱۲۳ and Arabic ones ٠١٢٣; bound to a plain input, that is what wire:model posts. mds:input is flux:input with the x-mds-digits directive on the control: digits are rewritten to Latin as they are typed, pasted or dropped, so the value the server receives is always the machine form. Every flux:input prop and attribute passes straight through.

Mobile number 
<mds:input label="Mobile number" placeholder="Try typing ۰۹۱۲ here" />

Digits only

With only everything that is not a digit is dropped too — phone numbers, verification codes, card numbers — and mobile keyboards are asked for a numeric layout through inputmode="numeric". A caller's own inputmode wins.

Verification code 
<mds:input only label="Verification code" placeholder="12345" maxlength="5" class="w-40" />

Everything Flux's input does

Label, description, icons, clearable, copyable, viewable, mask, invalid and the validation state read from the error bag are all Flux's own. Only the digit handling is added. A mask decides the shape of the value itself, so leave only off when you use one — the digits still arrive Latin.

With Livewire

Because the digits are rewritten before the browser applies the keystroke, the field fires a single input event, already Latin — a wire:model.live request never carries a Persian digit. Text committed through an on-screen keyboard's composition step cannot be intercepted that early; a second pass normalises it on input and re-announces the value.

Mobile number 
<mds:input only wire:model="mobile" label="Mobile number" type="tel" />

Inside an RTL form

Numbers read left-to-right even on a right-to-left page. ltr marks the control so the kit's stylesheet keeps it LTR and end-aligned inside an RTL form — the same rule that already applies to type="tel". The field shows Latin digits by design: what is on screen is exactly what will be posted.
